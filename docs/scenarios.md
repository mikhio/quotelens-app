# Сценарии и проверка QuoteLens

Запустите отдельный экземпляр по [README](../README.md). Для свежего поиска нужен настроенный провайдер; для арифметических проверок есть сохранённые сценарии. Таблицы задают ожидаемое поведение и не заменяют фактический прогон.

## 1. Закупка осциллографов

**Вход:** «Осциллограф цифровой, не менее 4 каналов, полоса пропускания не менее 100 МГц»; количество — 3 шт.

1. Введите описание, нажмите «Проверить позиции» и проверьте количество, единицу и обязательные признаки.
2. Оставьте поиск по всему интернету и режим готовности позиций; задайте допустимое время.
3. Запустите исследование, откройте найденное предложение и его доказательства.
4. Проверьте решение по каналам, полосе, единице цены и НДС. Скачайте PDF и DOCX после завершения.

**Ожидаемый результат:** сопоставление выполнено по характеристикам. Прибор с 2 каналами или полосой 30 МГц исключён с причиной, отсутствие характеристики отмечено для проверки. По каждой цене можно открыть источник и цитату с датой получения. Если набраны минимум три разных поставщика и CV всех сопоставимых цен ≤ 33%, профиль готовности выполнен. Иначе указан недостаток данных, частичный результат сохранён. Конкретная рыночная цена заранее не задаётся.

## 2. Бумага с разными упаковками

**Вход:** «Бумага офисная A4, 80 г/м², 500 листов в пачке»; количество — 100 пачек.

1. Проверьте формат, плотность, число листов и единицу потребности.
2. Запустите поиск. Среди предложений проверьте карточку пачки и карточку коробки.
3. Откройте подтверждение фасовки и сравните исходную цену с нормализованной.
4. Уточните неподтверждённое значение с сохранением основания либо исключите предложение. Проверьте пересчёт и выгрузку.

**Ожидаемый результат:** коробка переводится в пачки только при подтверждённом количестве пачек; бумага иной плотности исключается. Неизвестные НДС и единица продажи остаются видимыми. Предварительная оценка, если доступна, помечена отдельно от строгого результата; её допущения перечислены.

Для арифметики можно использовать **вымышленные** цены с одинаковым подтверждённым НДС от трёх тестовых продавцов:

| Тестовое предложение | Цена за пачку |
| --- | ---: |
| Коробка из 10 пачек за 4 500 ₽ | 450 ₽ |
| Пачка за 480 ₽ | 480 ₽ |
| Коробка из 5 пачек за 2 350 ₽ | 470 ₽ |

Среднее: `(450 + 480 + 470) / 3 = 466,666… ₽`. Стоимость 100 пачек после округления итоговой суммы до копеек — **46 666,67 ₽**. Это тестовые входы, а не цены реальных продавцов.

## 3. Многопозиционное ТЗ и передача результата

**Вход:** файл DOCX/TXT/MD или PDF с текстовым слоем, содержащий несколько позиций и их количества. Для проверки загрузки есть небольшие файлы в `tests/fixtures/specifications/`.

1. Прикрепите файл, проверьте позиции и общие условия. Уточните неизвестное количество.
2. Выберите общее время исследования или общее число найденных цен. Проверьте навигацию по позициям во время поиска и после него.
3. Закройте вкладку и откройте приложение заново: исследование доступно в серверной истории.
4. Скачайте документы и откройте сохранённую версию по созданной приложением ссылке.

**Ожидаемый результат:** позиции обрабатываются в рамках одной закупки и общего бюджета. Если часть позиций не рассчитана, сумма показана как частичная и перечислены пропуски. PDF/DOCX содержат всю закупку независимо от открытой позиции, фильтра и страницы таблицы. HTML открывается без сети и содержит результат для получателя. Ссылка открывает сохранённую версию; последующие исправления рабочего исследования не меняют уже переданный снимок.

## Проверка граничных случаев

| Условие | Ожидаемое поведение |
| --- | --- |
| Только одно надёжное предложение при профиле трёх поставщиков | Строгий итог отсутствует; указано, чего не хватает. Неизвестное не заменяется нулём. |
| Две карточки одного продавца и модели | Дубль связан с исходной карточкой и не увеличивает число независимых предложений. |
| Товар подходит по названию, но нарушает обязательный параметр | Исключение с конкретной причиной. |
| Цена есть, обязательная характеристика не подтверждена | Предложение требует проверки; модельная оценка не заменяет доказательство. |
| RUB и USD без основания для пересчёта | Валюты не усредняются как одинаковые числа. |
| Источник возвращает 403, CAPTCHA, таймаут или страницу без цены | Ошибка/пробел сохранены; отсутствующая цена не выдумывается и не заменяется старой. |
| Истекло время, исчерпан бюджет или нажата отмена | Сохранены данные, расход и причина остановки. Полнота рынка не заявляется. |
| PDF состоит из сканов | Сообщение о необходимости OCR; пустой разбор не выдаётся за успех. |
| Нет ключа модели | `/api/config` сообщает отсутствие настройки; живой запрос не подменяется синтетикой. |
| Исправление из устаревшей вкладки | Конфликт ревизий требует обновления; чужое изменение не затирается молча. |

## Воспроизводимая API-приёмка

Список сохранённых наборов доступен в `GET /api/scenarios`. `real_snapshot` означает сохранённые реальные страницы, `synthetic` — вымышленные тестовые данные. `POST /api/search` с `mode: "snapshot"` и `scenario_id` применяет требования к сохранённому набору. Дата воспроизведения не делает старую цену свежей; для нового сетевого поиска нужен режим `live`.

Из корня репозитория, против отдельного запущенного тестового экземпляра:

```bash
QUOTELENS_BASE_URL=http://127.0.0.1:8765 python3 -m unittest discover -s tests -p 'test_acceptance.py' -v
```

Без переменной адреса HTTP-приёмка явно пропускается; с заданным адресом недоступность сервера считается ошибкой. Модульные тесты запускаются отдельно:

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют расчёты, извлечение, ограничения, ревизии и API. Часть проверок использует сохранённые страницы или контролируемые ответы; успешный прогон таких тестов сам по себе не подтверждает доступность внешней модели и сайтов.
