# QuoteLens

QuoteLens помогает подготовить обоснование начальной цены закупки: разобрать техническое задание, найти публичные предложения, проверить сопоставимость и выгрузить расчёт вместе с источниками.

**ТЗ → проверка позиций → поиск → сопоставление предложений → расчёт → PDF и редактируемый DOCX.**

Пользователь вводит описание или прикрепляет DOCX, TXT, MD и PDF с текстовым слоем. Перед поиском он проверяет позиции, количества, единицы и требования. У найденных предложений видны цена, характеристики, поставщик, дата получения и цитаты из сохранённого источника. Можно исправить данные с сохранением истории, исключить предложение, продолжить поиск и передать результат по ссылке.

Модель выбирает поисковые действия и предлагает извлечённые факты. Код проверяет подтверждения, сопоставимость и арифметику. Неполные данные дают предварительную оценку или сообщение о недостатке данных. Приложение не утверждает юридическую корректность закупки.

## Быстрый запуск

Нужны Git, Docker Engine с Docker Compose v2 и интернет для сборки. Живой поиск дополнительно требует доступного провайдера модели, его ключа и доступа к публичным сайтам. Python, Playwright и Chromium устанавливаются в образ; отдельная база данных не нужна — используется SQLite.

```bash
git clone https://github.com/mikhio/quotelens-app.git
cd quotelens-app
cp .env.example .env
mkdir -p secrets
chmod 700 secrets
touch secrets/model.key
```

Для живого поиска откройте `secrets/model.key` в текстовом редакторе и сохраните в нём свой API-ключ. В `.env` задайте `MODEL_API_BASE` и `MODEL_NAME`: нужен совместимый Chat Completions API с вызовом инструментов. В примере настроек указан OpenRouter; доступность выбранной модели и средства на счёте проверяются у провайдера.

Пустой файл ключа позволяет запустить интерфейс, API и сохранённые проверочные сценарии. Новая закупка без настроенной модели не подменяется учебными данными.

```bash
chmod 444 secrets/model.key
docker compose up --build -d
curl --fail http://localhost:8765/health
```

Откройте **http://localhost:8765**. Статус настройки модели доступен в `/api/config`, ключ в ответ не попадает. Compose подключает файл ключа только для чтения; он исключён из Git и Docker-контекста.

Остановить приложение, сохранив исследования и квоты:

```bash
docker compose down
```

Результаты хранятся в постоянном томе `results`. Не добавляйте `-v` к остановке, если нужно сохранить базу. После изменения `.env` пересоздайте контейнер командой `docker compose up -d`. Таблица настроек, различия лимитов и запуск без Docker — в [конфигурации](docs/configuration.md).

## Как проверить продукт

1. Введите ТЗ или прикрепите файлы и нажмите «Проверить позиции».
2. Проверьте позиции: количество, единицу, характеристики и общие условия. Неизвестные значения нужно уточнить.
3. Выберите область поиска и условие завершения. По умолчанию это готовность каждой позиции: минимум три сопоставимых предложения разных поставщиков и коэффициент вариации не выше 33%, с ограничением времени.
4. Запустите поиск. Предложения, просмотренные источники и частичный результат сохраняются на сервере. Закрытие вкладки не отменяет исследование.
5. Сравните предложения и доказательства, при необходимости сохраните уточнения или исключения. Затем скачайте PDF/DOCX. HTML и JSON доступны как дополнительные форматы.

Можно искать до заданного числа предложений с ценой или до истечения времени. Счётчик найденных цен и готовность к расчёту различаются: карточке с ценой ещё может не хватать характеристик или условий. Поиск также может закончиться из-за отмены, бюджета, ошибки провайдера или исчерпания найденных ссылок; причина остаётся в результате.

| Пример входа | Ожидаемый результат |
| --- | --- |
| «Осциллограф цифровой, не менее 4 каналов, полоса не менее 100 МГц», 3 шт. | Карточки сопоставлены по каналам и полосе. Модель с 2 каналами исключена; неподтверждённые параметры видны. Расчёт появляется при выполнении профиля, иначе указано, каких данных не хватает. |
| «Бумага офисная A4, 80 г/м², 500 листов в пачке», 100 пачек. | Цена коробки приведена к пачке только при подтверждённом количестве пачек. Бумага другой плотности исключена; неизвестные НДС и единица цены требуют проверки. Отчёт показывает исходные цены и преобразования. |

Шаги, воспроизводимая арифметика и проверка отказов — в [сценариях](docs/scenarios.md). Живой поиск зависит от внешних сайтов: конкретные цены и достаточная выборка заранее не гарантируются.

## Зависимости и ограничения

Для живого исследования используются внешний API модели, поиск DuckDuckGo и публичные HTTPS-страницы. При недоступности основной выдачи предусмотрен резервный поиск Exa через OpenRouter; этот путь зависит от возможностей и оплаты провайдера. Другой совместимый провайдер может выполнять основной модельный цикл без такого резерва. Зависимости Python закреплены в [requirements.txt](requirements.txt).

Передавайте только открытые неконфиденциальные сведения: текст ТЗ и фрагменты источников могут обрабатываться внешней моделью. Ключ задаёт оператор сервера, посетитель его не вводит.

Именной источник в интерфейсе задаёт область обычного веб-поиска. Это не подтверждение доступности сайта или готовой интеграции с его API. Полноценные коннекторы ЕИС/ГИСП, авторизованные площадки, OCR сканов и извлечение предложений из произвольных PDF поставщиков пока не реализованы. CAPTCHA, robots и сетевые отказы могут ограничивать результат. Юридическая независимость поставщиков и итоговая НМЦД требуют проверки специалистом.

## Проверки для разработчика

В локальном Python-окружении с установленными зависимостями:

```bash
python3 -m unittest discover -s tests -v
```

HTTP-приёмку запускайте против отдельного тестового экземпляра: тесты создают записи в его базе. Для экземпляра, поднятого Compose по этой инструкции:

```bash
QUOTELENS_BASE_URL=http://127.0.0.1:8765 python3 -m unittest discover -s tests -p 'test_acceptance.py' -v
```

Без `QUOTELENS_BASE_URL` HTTP-приёмка пропускается явно. Сохранённые реальные страницы и синтетические наборы проверяют воспроизводимость и арифметику; они помечены отдельно и не доказывают свежий поиск рынка.
